# Changelog

Condensed. The full notes for each release, with reproductions and migration
detail, are on
[GitHub Releases](https://github.com/qurit/rt-utils/releases).

:::{tip}
If you are upgrading from 1.x, read {doc}`concepts/mask-layout` and
{doc}`concepts/contour-placement`. Those are where the behaviour changed.
:::

## 2.4.0

**Added**

- {meth}`~rt_utils.rtstruct.RTStruct.delete_roi`, so that `add_roi` finally
  has an inverse. All three sequences are cleaned up, and numbering is left
  with a gap on purpose.
- `roi_interpreted_type` on {meth}`~rt_utils.rtstruct.RTStruct.add_roi`, which
  sets `RTROIInterpretedType` so a planning system can tell a target from an
  organ at risk. Previously always written empty.

**Changed**

- Diagnostics go to module loggers rather than stdout. If you relied on seeing
  `Writing file to ...`, call `logging.basicConfig(level=logging.INFO)`.

**Fixed**

- `RTStructMerger` could not merge two sets that shared an ROI name. The
  rename path added a string to a `Dataset` rather than to its `ROIName`, and
  had never run successfully.
- `RTStructMerger` could assign a colliding `ROINumber` where the destination
  had a gap.

## 2.3.0

Four silent wrong-data fixes and a supported NIfTI converter.

**Added**

- {func}`rt_utils.nifti.nifti_to_mask` resamples a NIfTI segmentation onto
  the series grid, reading both affines. `label=` selects one structure from a
  multi-label file.
- `match_by="position"` on
  {meth}`~rt_utils.rtstruct.RTStruct.get_roi_mask_by_name`, for images whose
  `SOPInstanceUID`s were regenerated by anonymisation.
- `force=` on both builder entry points, for files without the standard
  preamble or file meta.

**Fixed**

- **Contours were placed by averaged slice spacing.** On an unevenly spaced
  series every slice between the first and last was written to a position no
  slice occupies.
- **Open contours were filled as closed regions.** A C-shaped applicator
  channel of 65 voxels came back as a solid 579.
- **Duplicate and overlapping series were stacked silently.** Copies are now
  collapsed by `SOPInstanceUID`; distinct images sharing a position raise.
- **A valid series could be invisible** behind `No DICOM Images found`,
  because pixel data was decoded to decide whether a file was an image.
- **Unmatched contours returned zeros** instead of raising.

**Removed**

- `nifti2rt.py`, which defined one function that nothing called and that could
  not run.

## 2.2.0

**Mask axis order corrected.** Masks are indexed `(Rows, Columns, Slices)`
throughout. They had been *allocated and validated* as `(Columns, Rows,
Slices)` while every geometric computation used the opposite order, since
2020.

A square series is unaffected in plane. On a non-square series it was wrong in
both directions: ROIs past the shorter dimension were silently dropped on
read, and correct masks were rejected on write.

`use_pin_hole` was affected on square series too. It sampled the mask
transposed, so on any region not symmetric about `y = x` the channel was never
cut.

:::{important}
If you transposed your masks to work around this on a non-square series,
remove the transpose.
:::

## 2.1.1

- A mask with the wrong in-plane shape is rejected at the point of the
  mistake, rather than failing later inside NumPy with a broadcast error.

## 2.1.0

**Added**

- `coordinate_space="pixel"` on
  {meth}`~rt_utils.rtstruct.RTStruct.add_roi_from_coordinates`, taking
  `[column, row, slice_index]`.
- Mask smoothing: `apply_smoothing="2d"` or `"3d"`, with `smoothing_function`
  as a hook for your own implementation.
- `get_roi_names(geometry=...)` to filter by `ContourGeometricType`.

**Fixed**

- A series missing `StudyID` no longer raises. It is Type 2, permitted to be
  empty.
- A series missing `ImagePositionPatient` now explains itself. It is Type 1
  and cannot be defaulted; substituting an origin would relocate the whole
  ROI.

## 2.0.0

**The default contour placement changed.** `contour_mode` now defaults to
`"voxel_edge"`. Contours had been traced through voxel *centres*, which
understates a structure by half a voxel on every side, which is 55 % of the
area of a 3 × 3 voxel region.

**Contours are now rasterised by voxel centre.** A voxel is set when its
centre lies inside the contour, which is correct for contours written either
way, so files from other software are read more accurately too.

Pass `contour_mode="voxel_center"` to reproduce the previous contours exactly.

**Added**

- {meth}`~rt_utils.rtstruct.RTStruct.add_roi_from_coordinates`.
- DICOM data already in memory: `create_new` and `create_from` accept lists of
  datasets, and {meth}`~rt_utils.rtstruct.RTStruct.save_to_memory` returns a
  rewound `BytesIO`.
- A round-trip conformance suite over eight contour topologies.

## 1.4.1

- `add_roi` no longer reuses an `ROINumber` that is still in use. The number
  came from `len(sequence) + 1`, which collides wherever an ROI has been
  deleted elsewhere.
- Depends on `opencv-python-headless`, so no `libGL` system package is needed.

## 1.4.0

- **Single-voxel ROIs were silently dropped.** A one-point contour was
  labelled `CLOSED_PLANAR` and then discarded by the filter.
  `ContourGeometricType` now follows the point count, per PS3.3 C.8.8.6.1.
- **ROIs whose names differed only in case were unreachable.** Exact matching
  is the default; `case_sensitive=False` is opt-in.
- Reading one- and two-point contours no longer raises on OpenCV 4.x.
- A single point rasterises to one voxel, not five.
- Removed a dependency on the PyPI `dataclasses` backport, which shadowed the
  standard library module.
- `requires-python` is now `>=3.9`; CI covers 3.9 to 3.13.
